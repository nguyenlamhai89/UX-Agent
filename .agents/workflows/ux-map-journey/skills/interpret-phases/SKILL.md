# interpret-phases

## Description

The `interpret-phases` skill is designed to bridge the gap between raw extracted data and the final compiled journey map. It takes raw `extracted-<phase>.md` files generated by the `extract-phases` skill and uses the built-in Antigravity AI to interpret their contents. The AI reads each file one by one (sequentially to prevent hallucination) and outputs an `interpret-<phase>.md` file containing a precise Markdown table.

This skill is orchestrated by `ux-map-journey` and must run after `extract-phases` and before `extract-map`.

## Input

- **Type**: `dict`
- **Format**: Requires a `folder_path` pointing to the `Journey Map` folder containing the `extracted-<phase>.md` files.
- **Location**: `request_body`
- **Input File(s)**:
  - `extracted-<phase>.md` — The extracted phase document generated by the `extract-phases` skill.

- **Examples**:

  **Example 1** — Single request:
  ```json
  {
    "folder_path": "/path/to/Journey Map/"
  }
  ```

## Output

- **Type**: `dict`
- **Format**: Returns a status and a list of paths to the newly created `interpret-<phase>.md` files.
- **Location**: `response_body`
- **Output File(s)**:
  - `interpret-<phase>.md` — The interpreted structured table for the specific phase.

- **Examples**:

  **Example 1** — Success response:
  ```json
  {
    "status": "success",
    "result_paths": [
      "/path/to/Journey Map/interpret-Awareness.md",
      "/path/to/Journey Map/interpret-Consideration.md"
    ]
  }
  ```

- **Specific format output (e.g., Markdown template)**:
  ```markdown
  # Interpret - [Phase Name]

  | Category | Details |
  | :--- | :--- |
  | **Stage goal** | ... |
  | **Stage touchpoints** | ... |
  | **Stage actions** | ... |
  | **Stage pain points** | ... |
  | **Stage emotion (1-5)** | ... |
  | **Stage opportunities & metrics** | ... |
  ```

## Custom Instructions

- Read the input text from the `extracted-<phase>.md` file.
- Analyze the contents and map the information directly into a Markdown table with exactly the following rows:
  1. **Stage goal**
  2. **Stage touchpoints**
  3. **Stage actions**
  4. **Stage pain points**
  5. **Stage emotion (1-5)** (Must be a numeric value from 1 to 5, where 1 is extremely negative and 5 is extremely positive, based on the context).
  6. **Stage opportunities & metrics**
- Ensure that the output strictly adheres to the Markdown table format without any additional conversational text or hallucinations.
- Process files sequentially, one by one, to ensure maximum accuracy and prevent hallucinations from context bleeding between phases.

# How to Fill Out Customer Journey Map Sections After In-Depth Interviews

### 1. Stage Goal
What the customer genuinely wants to achieve during this specific stage (from their perspective, not the business's sales goals).
*   **How to extract from interviews:** Look for phrases in the answers that indicate desires or reasons behind their actions. Examples: *"I wanted to find..."*, *"At that time, I just needed..."*, *"I was hoping that..."*
*   **How to write:** Concise, starting with an action verb.
*   **Examples:**
    *   *Search Stage:* Search for and filter 3 laptop models suitable for graphic design needs.
    *   *Payment Stage:* Complete the transaction quickly and securely without system errors.

### 2. Stage Touchpoints
The points of interaction between the customer and the brand (or the surrounding environment) during that stage.
*   **How to extract from interviews:** Note all channels, devices, people, or documents mentioned by the user. Examples: *"I browsed Facebook..."*, *"I asked my friends..."*, *"I accessed the website on my phone..."*, *"The consultant told me..."*
*   **How to write:** List specific nouns.
*   **Examples:** Website (mobile), Fanpage Messenger, In-store staff, Order confirmation email, Product packaging.

### 3. Stage Actions
The concrete, physical steps the customer took to achieve their goal in that stage.
*   **How to extract from interviews:** Focus on verbs indicating user actions. Examples: *"I typed a search..."*, *"I read reviews..."*, *"I compared prices between the two..."*
*   **How to write:** List in chronological order (bullet points can be used).
*   **Examples:**
    1. Enter the keyword "graphic design laptop under 25M VND" on Google.
    2. Click on the first 3 results.
    3. Read reviews from previous users.
    4. Message the Fanpage to ask about the warranty policy.

### 4. Stage Pain Points
Obstacles, frustrations, anxieties, or barriers that make it difficult for customers to achieve their goals.
*   **How to extract from interviews:** Look for sections where users complain, show confusion, or abandon actions. Examples: *"I found it very annoying when..."*, *"The information here was too vague..."*, *"It took too long, so I closed it..."*
*   **How to write:** Clearly describe the problem and its root cause (if any).
*   **Examples:**
    *   Product configuration information on the website is inconsistent with the staff's advice.
    *   Fanpage response time is too slow (over 30 minutes).
    *   Lack of popular e-wallet payment methods.

### 5. Stage Emotion (Scale of 1 to 5)
The customer's level of satisfaction or emotional state during that stage, typically represented on a scale from 1 (very frustrated/disappointed) to 5 (very satisfied/excited).

#### Emotion Scale Table (1 to 5)

| Score | Emotion Level | Primary Emoji | Emoji Name | Alternative Emoji | Alternative Name | Typical User Context / Triggers |
| :---: | :--- | :---: | :--- | :---: | :--- | :--- |
| **1** | **Very Negative** | 😡 <br>*(Use when users experience blocked workflows, poor service, or feel cheated)* | Angry Face | 😭 <br>*(Use when users feel completely helpless, overwhelmed, or suffer severe data/financial loss)* | Loudly Crying Face | Critical system errors, transaction failures, extreme frustration, or unhelpful customer support. |
| **2** | **Slightly Negative** | 🙁 <br>*(Use when users encounter minor UI friction, slow load times, or mild disappointment)* | Slightly Frowning Face | 🤨 <br>*(Use when users express confusion, skepticism, or doubt about information validity)* | Face with Raised Eyebrow | Minor delays, confusing navigation, unclear pricing, or lack of trust in the system. |
| **3** | **Neutral** | 😐 <br>*(Use when users complete routine, expected tasks without strong positive or negative feelings)* | Neutral Face | 😑 <br>*(Use when users perform tedious but necessary steps, like reading terms of service)* | Expressionless Face | Routine steps requiring low cognitive load (e.g., logging in, entering basic contact info). |
| **4** | **Positive** | 🙂 <br>*(Use when users experience a smooth, frictionless, and intuitive process)* | Slightly Smiling Face | 😊 <br>*(Use when users feel reassured, confident, or pleased with proactive guidance)* | Smiling Face with Smiling Eyes | Smooth process completion, helpful support, clear instructions, or fast response times. |
| **5** | **Very Positive** | 😁 <br>*(Use when users achieve their primary goals easily and feel highly satisfied)* | Beaming Face with Smiling Eyes | 🤩 <br>*(Use when users experience an unexpected "wow" moment, delight, or premium feature)* | Star-Struck | Delight moments, unexpected benefits, exceeding expectations, or highly personalized service. |

*   **How to represent:** Represent strictly in the format: `[Score 1-5] - [Emotion Level] [Primary/Alternative Emoji]` (e.g., `2 - Slightly Negative 🙁`, `5 - Very Positive 😁`).

### 6. Stage Opportunities & Metrics
*   **Opportunities:** Ideas or design/operational solutions to address the pain points identified above in order to improve the experience.
    *   *How to write:* Provide specific recommendations aimed at resolving the pain points.
    *   *Example:* Build an intuitive "Product Comparison" feature on the website; Set up an automated chatbot to answer frequently asked questions about the warranty within 1 minute.
*   **Metrics:** Quantitative indicators that help the business measure if the improvement solution is effective.
    *   *How to write:* Use common industry-standard measurement metrics (KPIs/UX Metrics).
    *   *Example:* Bounce rate, Average response time, Conversion rate, Customer Satisfaction Score (CSAT).

---

### Key Takeaways When Writing:
*   **Maintain Objectivity:** Avoid inserting the subjective opinions of the product team. Stick closely to what customers actually said and did during the interviews.
*   **Use Direct Quotes:** Where appropriate, insert a few short, direct quotes from customers at each stage to help stakeholders better empathize with the user experience.

## Sequence Diagram

```mermaid
sequenceDiagram
    autonumber
    actor User
    participant Orchestrator
    participant Skill

    User->>Orchestrator: Send request (folder_path)
    activate Orchestrator
    Note over Orchestrator: Route to interpret-phases

    Orchestrator->>Skill: Execute (folder_path)
    activate Skill
    
    loop For each extracted-<phase>.md
        Note over Skill: Read file sequentially
        Note over Skill: Built-in AI interprets content
        Note over Skill: Write interpret-<phase>.md
    end

    alt Success
        Skill->>Orchestrator: Return success status and result_paths
        deactivate Skill
        Orchestrator->>User: Respond with formatted result
        deactivate Orchestrator
    else Failure
        Skill->>Orchestrator: Return error status and error message
        deactivate Skill
        Orchestrator->>User: Respond with fallback / error message
        deactivate Orchestrator
    end
```

## Error Handling & Fallbacks

| Error Code | Message | Fallback Behavior |
| --- | --- | --- |
| `INVALID_INPUT` | The input folder path is missing or invalid. | Return a clear validation error to the user. |
| `FILES_NOT_FOUND` | No `extracted-<phase>.md` files were found in the folder. | Return a message indicating that the preceding skill might not have run. |
| `AI_PROCESSING_ERROR` | The built-in AI failed to parse or generate the output. | Log the error and skip the problematic file, or return a failure message if critical. |
